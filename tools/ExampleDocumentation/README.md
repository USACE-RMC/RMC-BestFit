# Maintaining the example collection

Run these tools from the repository root. They preserve saved numerical inputs and results; changing those requires a separate, explicitly reviewed decision.

- `project_inventory.py` reads SQLite in immutable, read-only mode. Its inventories include metadata, decoded configuration, input counts, diagnostics and a hash of every cell.
- `update_descriptions.py manifest.json` validates the source hashes and lists proposed description edits. `--apply` retains original files and writes an audit receipt. Each edit names the table, rowid, expected name and replacement description. The transaction compares every cell before committing and rolls back any unrelated change. Description updates do not delete rows. Manifests containing the legacy `removeAbomTest` key are rejected before any project, backup or receipt is written.
- `render_screenshots.py --only <substring> --refresh` exports native plot views or captures current UI panels into each tutorial's `screenshots/` directory. Without `--refresh`, it verifies saved source/output hashes and does not overwrite captures. The canonical `examples/screenshot-manifest.json` records every contributor PNG's disposition, exact source/element/view or UI selection, source hash, output hashes and compressed `.json.gz` capture snapshot. An omitted legacy or changed-horizon image has an explicit reason; no contributor snapshot is silently treated as current evidence.
- `render_examples.py --only <example-slug> --refresh` opens disposable project copies through `PlotReferenceExporter`, then uses the portable skill renderer for PNG/SVG output. Compressed PlotSpec files retain the exact display inputs. `--refresh` is required after changing desktop factories or runtime dependencies; otherwise source-identical cached geometry can be reused.
- `render_docs.py --only <chapter-or-slug>` checks local files and Markdown heading anchors and builds HTML previews under `artifacts/example-documentation/site/`. Links to Markdown outside `examples/` open the actual source file. Install `markdown-it-py` alongside the plotting requirements, then serve the repository root on loopback to inspect these pages. The preview does not replace individual figure review.

The Python figure manifest lives in `examples/figure-manifest.json`; native captures use `examples/screenshot-manifest.json`. A figure must identify its source project, named element, supported plot ID, variant and output prefix. The renderer fails on unsupported geometry or an empty plot instead of replacing it with invented data. Most views display saved results. Threshold diagnostics invoke the desktop's diagnostic fits on the saved source series; they do not replace a saved analysis.

An optional `legendLocation` selects `best`, `upper left`, `upper right`, `lower left`, `lower right` or `outside right` when automatic placement covers observations. Trace plots place legends outside the axes so diagnostic excursions remain visible. This display-only choice is recorded in the PlotSpec. The historical description edits and their before/after database hashes are recorded in `examples/metadata-audit.json`. That receipt preserves the original transaction, including its specific row-removal/tree-restoration exceptions; later project bytes need not match its after-hashes. Do not rewrite those historical hashes. Hash a current database only after closing the SQLite writer so WAL changes have reached the main file.

For each tutorial, review the actual database, write the source and assumptions in plain language, render each figure, inspect the individual PNG and rendered Markdown page, and check local links. For native views, confirm the selected element and variant, parameter index, axes, series population and interval meaning against the saved source; do not replace a residual ACF with a parameter-chain ACF or a scatter view with density contours. UI captures must show the current source project and named selection. Keep the app snapshot and Python companion identities explicit. Confirm all unapproved SQLite cells remain identical. Run the relevant Python checks and the repository's required fast .NET gates before a local commit. The [example limitations](../../docs/example-limitations.md) describe unresolved source and study judgments.

The Back Creek manifest entry explicitly sets `legacySavedFrequency`. Its older model-column name prevents current desktop loading of an intact GMM fit. This option reads the original probability/curve/bound arrays from the legacy row in immutable mode and overlays them on the desktop observations. It rejects an already populated fitted plot, misaligned arrays, invalid probabilities and inverted bounds. It does not decode an uncertainty ensemble, migrate a model or change any result. The PlotSpec records the source columns and display correction.

For covariate time-series residuals, the desktop exporter reads the saved parameter vector and calls BestFit's existing residual method. Older figures used this path to bypass the covariate-loading reset fixed in v2.0.1 without changing the model or source. The capture retains its original identity; [example limitations](../../docs/example-limitations.md) distinguish that historical display path from remaining source and forecast assumptions.

Sadie Niblett's citation credit is retained in `CITATION.cff`. Contributor-image dispositions remain in `examples/screenshot-manifest.json`; `docs/sadie-data-disposition.json` records which target data files or absences were retained. Native capture receipts preserve source-before/source-after hashes, exact plot or panel selection and output hashes. Keep native and Python destinations separate, preserve existing scientific tables, and use disposable project/DSS copies for captures. A changed forecast horizon is a different scientific configuration, not a cosmetic screenshot update.

## Historical Python capture provenance

Each `examples/figure-manifest.json` entry includes `captureProvenance` for the published Python PNG, SVG and compressed PlotSpec. It preserves the source-project SHA-256 used for that capture, output hashes, pixel dimensions and the recorded review timestamp. It does not claim the present database is byte-identical to the capture source or that a new visual or scientific review occurred. The original capture source hashes remain unchanged even when a later project differs.

The renderer selects views from the manifest and writes new render receipts under `artifacts/example-documentation/`; it does not automatically update the published `captureProvenance`. After an intentional refresh, verify the new source/view identity and inspect the outputs before updating that entry from the new receipt. Do not copy a current project hash onto an existing image. Keep session test logs, page-review checklists, package receipts and superseded QA records in local artifacts.
